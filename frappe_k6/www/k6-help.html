frappe_k6 — User Manual

Complete guide to installing, configuring, and running load tests with K6, Prometheus, and Grafana on any Frappe site.

K6 v2+ Frappe v15 / v16 Prometheus v2.52 Grafana v10+ Ubuntu / Debian

2. Installation

Step 1 — Get the app into your bench

cd /path/to/your/bench
bench get-app https://github.com/your-org/frappe_k6.git

Step 2 — Install on a site

bench --site <your-site.com> install-app frappe_k6
ℹ What happens automatically The installer runs a full plug-and-play setup:
  • Creates the k6_tests/reports/ directory
  • Populates Monitor Settings with your server IP, ports, and paths
  • Creates 6 sample Load Test Configs (smoke, load, stress, spike, soak, custom)
  • Installs K6 via APT (if not present)
  • Downloads and starts node_exporter on port 9100
  • Downloads and starts Prometheus on port 9090
  • Starts the frappe_k6 exporter on port 9200
  • Installs and starts Grafana on port 3000, with Prometheus datasource & dashboard pre-loaded

Step 3 — Build assets

bench build --app frappe_k6
bench --site <your-site.com> clear-cache

7. Grafana

Open: http://<server-ip>:3000 — Default login: admin / admin (you will be prompted to change it on first login).

Pre-provisioned Dashboard

Navigate to Dashboards → Browse → frappe_k6 — System & Load Test Monitor. This dashboard includes:

  • CPU gauge and timeline (system + user + kernel split)
  • Memory usage timeline (used / available / cached)
  • Disk usage gauge
  • Network I/O bytes/s (per interface)
  • Disk I/O read/write bytes/s
  • TCP connections (established + TIME_WAIT)
  • System load averages (1m / 5m / 15m)
  • Open file descriptors & active processes
ℹ Data source All panels use the pre-provisioned Prometheus datasource (uid: prometheus), pointing to http://localhost:9090. If Prometheus is on a different host, go to Connections → Data sources → Prometheus and update the URL.

Opening Grafana from Frappe

Go to Monitor Settings → External Links → Open Grafana. This opens the URL configured in the grafana_url field.

10. Troubleshooting

Grafana not opening from External Links

Symptom — Clicking "Open Grafana" does nothing or shows a blank page.
  1. Check that grafana_url in Monitor Settings starts with http:// or https://.
  2. Verify Grafana is running: systemctl is-active grafana-server
  3. Test in terminal: curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/api/health — should return 200.
  4. Check firewall: sudo ufw status — port 3000 must be allowed from your workstation.

Prometheus not accessible

  1. systemctl is-active prometheus — must be active.
  2. curl http://localhost:9090/api/v1/status/runtimeinfo — should return JSON.
  3. If inactive: sudo systemctl start prometheus && sudo systemctl enable prometheus
  4. Logs: journalctl -u prometheus -n 50 --no-pager

K6 not found / test won't start

  1. which k6 — if empty, K6 is not on PATH.
  2. Re-run installer: bench --site <site> execute frappe_k6.install._install_k6
  3. Or install manually: k6.io/docs/get-started/installation
  4. After installing, update the K6 Binary Path in Monitor Settings to the full path returned by which k6.

Metrics not appearing in K6 Dashboard

  1. Open browser DevTools (F12) → Console tab. Look for red errors.
  2. Check that frappe_k6.api.system_metrics.get_all_metrics returns data:
    curl http://localhost:<port>/api/method/frappe_k6.api.system_metrics.get_all_metrics
  3. Run bench restart to pick up any code changes.
  4. Verify the bench is running: bench status

Dashboard not updating (metrics stuck)

  1. Check Dashboard Refresh in Monitor Settings — must be > 0.
  2. Hard-refresh the browser: Ctrl+Shift+R (Windows/Linux) or Cmd+Shift+R (Mac).
  3. Check browser console for JavaScript errors.

frappe_k6 Prometheus target is "down"

  1. Check the exporter: systemctl is-active frappe_k6_exporter
  2. Test it: curl http://localhost:9200/metrics | head -5 — should return Prometheus text lines.
  3. If inactive: sudo systemctl start frappe_k6_exporter
  4. View logs: journalctl -u frappe_k6_exporter -n 30 --no-pager

Load test reports: Permission denied

  1. Check the reports directory exists and is writable:
    ls -la $(bench --site <site> execute "frappe.db.get_single_value('Monitor Settings','k6_reports_dir')")
  2. Fix permissions: chmod 755 /path/to/reports/

Grafana dashboard shows "No data"

  1. Verify the Prometheus data source: Grafana → Connections → Data sources → Prometheus → Test.
  2. Check Prometheus has data: open http://<server>:9090/graph and query node_cpu_seconds_total.
  3. Check node_exporter: systemctl is-active node_exporter
  4. Wait 1–2 scrape cycles (30 s) after starting services for data to appear.

11. Best Practices

Choosing the Right Scenario Type

  • Always start with a smoke test to verify your endpoints work before running heavier tests.
  • Use load test as the baseline for production capacity planning.
  • Run stress tests in a staging environment — they will push the server to its limits.
  • Schedule soak tests overnight to avoid impacting daytime users.

Load Test Configuration

  • Set Think Time to 1–2 seconds to simulate realistic user behaviour; 0 is unrealistically aggressive.
  • Use Weight % to mirror real traffic patterns (e.g. 70% GETs, 20% POSTs, 10% DELETEs).
  • Use Session (Frappe Login) auth for most Frappe APIs — the test runner handles cookie management automatically.
  • Keep the Expected Status accurate — a mismatch silently marks requests as failed.

Dashboard Performance

  • Set Dashboard Refresh to 5 seconds only while actively watching a test; set it to 15–30 otherwise.
  • Do not keep the K6 Dashboard open in multiple browser tabs simultaneously during a load test.

Prometheus & Grafana

  • Change the Grafana admin password immediately after first login.
  • To extend Prometheus TSDB retention beyond the default 15 days, add --storage.tsdb.retention.time=90d to the ExecStart line in /etc/systemd/system/prometheus.service, then sudo systemctl daemon-reload && sudo systemctl restart prometheus.
  • Back up ~/monitoring/prometheus/data/ regularly if you need historical metrics.

Production Checklist

  • ☐ Grafana admin password changed
  • ☐ All Monitor Settings URLs use the server's actual IP or domain (not localhost)
  • ☐ Firewall: ports 3000 and 9090 restricted to trusted IPs only
  • ☐ Reports directory on a disk with adequate free space
  • ☐ All four services set to auto-start: systemctl is-enabled prometheus grafana-server node_exporter frappe_k6_exporter
  • ☐ Ran a smoke test successfully before any heavier scenarios
