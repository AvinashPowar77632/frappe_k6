📌 Frappe K6 — Overview

A complete performance monitoring & load testing solution built into Frappe/ERPNext. Combines K6 load testing, Prometheus metrics, Grafana dashboards, and Loki log aggregation in a single app.

🔫
Load Testing
Run Smoke, Load, Stress, Spike & Soak tests against any API endpoint
📊
7 Dashboards
Expert Grafana dashboards for every layer of the stack
🌐
Remote Servers
Monitor multiple remote servers with node_exporter
📜
Log Aggregation
Loki + Promtail collect all Frappe, scheduler, worker & system logs
🔔
Real-time Alerts
Threshold-based colour coding on every gauge and stat panel
🤖
Auto-provisioned
One-command install — services, datasources & dashboards created automatically

🔍 Common Patterns & What They Mean

CPU Sawtooth Pattern

CPU rises then drops regularly → Scheduled job (cron/scheduler) running. Normal if predictable.

Memory Never Decreases

Memory grows but never falls → Memory leak. Identify the process with ps aux --sort=-%mem | head.

Disk IOWait Spikes with Slow Queries

IOWait & slow query count spike together → Database doing full table scans. Add indexes.

High P99 but Low P50

Most requests are fast but a few are very slow → Tail latency issue. Check for lock waits or GC pauses.

Redis Hit Rate Drops

Hit rate drops suddenly → Cache was flushed or TTLs too short. Check if a deployment cleared caches.

🌐 Remote Server Monitoring

📋 Overview

Add any Linux server to the monitoring system in 3 steps: install node_exporter on it, register it in Frappe, and Prometheus automatically starts scraping it.

Step 1 — Install node_exporter on the Remote Server

Run the installer script on the remote server (not this Frappe server).
# Option A: Use the bundled installer script (copy from this server first)
scp /home/erpadmin/eduv16/apps/frappe_k6/frappe_k6/setup/install_remote_exporters.sh user@remote-server:~/
ssh user@remote-server
chmod +x install_remote_exporters.sh
./install_remote_exporters.sh
# Option B: Manual install (Ubuntu)
wget https://github.com/prometheus/node_exporter/releases/download/v1.7.0/node_exporter-1.7.0.linux-amd64.tar.gz
tar xvf node_exporter-*.tar.gz
sudo mv node_exporter-*/node_exporter /usr/local/bin/
# Create systemd service
sudo tee /etc/systemd/system/node_exporter.service << 'EOF'
[Unit]
Description=Node Exporter
After=network.target
[Service]
ExecStart=/usr/local/bin/node_exporter
Restart=on-failure
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable --now node_exporter
# Verify
curl http://localhost:9100/metrics | head -3

Step 2 — Open Firewall on Remote Server

# Allow Prometheus server to scrape
sudo ufw allow from <PROMETHEUS_SERVER_IP> to any port 9100
# Verify port is listening
ss -tlnp | grep 9100

Step 3 — Register in Frappe

1
Go to Frappe → Remote Server → New
2
Fill in the fields
FieldValue
Server NameUnique short name — used in Grafana filter (e.g., prod-app-1)
IP AddressIP or hostname of the remote server
node_exporter Port9100 (default)
Environmentproduction / staging / development
Enabled✓ checked
3
Save — Prometheus auto-updates

Prometheus config is rewritten and reloaded automatically. Within 15 seconds, the server appears in Grafana.

🔧 Troubleshooting

🚦 Service Status Check (Run First)

systemctl status prometheus grafana-server loki promtail node_exporter frappe-k6-exporter redis_exporter 2>&1 | grep -E "●|Active:|failed"

❌ Grafana not accessible (port 3000)

sudo systemctl restart grafana-server
sudo journalctl -u grafana-server -n 50 --no-pager
# Check config
sudo cat /etc/grafana/grafana.ini | grep http_port

❌ Prometheus not collecting metrics

# Check targets
curl 'http://localhost:9090/api/v1/targets' | python3 -m json.tool | grep -A3 '"health"'
# Reload config
curl -X POST http://localhost:9090/-/reload
# Check logs
sudo journalctl -u prometheus -n 30 --no-pager

✅ Best Practices

🔐 Security

  • Change Grafana default password immediately after install
  • Never expose Prometheus (9090) or Loki (3100) to the internet — use firewall rules
  • Restrict node_exporter (9100) to Prometheus server IP only
  • Use HTTPS reverse proxy (nginx) in front of Grafana for production
  • Store API keys in Monitor Settings, not in test scripts

💾 Data Retention

ServiceDefault RetentionChange Setting
Prometheus15 daysAdd --storage.tsdb.retention.time=30d to service ExecStart
LokiUntil disk fullAdd retention_period: 720h to loki-config.yaml compactor section
GrafanaIndefinite (SQLite)Regular backup of /var/lib/grafana/grafana.db

📊 Dashboard Optimization

  • Use 30s refresh for production dashboards (avoids Prometheus overload)
  • Set default time range to Last 3 hours — long ranges slow Prometheus queries
  • Use the Server dropdown to filter — avoid loading all-server data at once
  • Collapse unused rows to speed up dashboard rendering

🔫 Load Testing Best Practices

  • Always run Smoke test first before stress/soak tests
  • Run load tests during off-peak hours in production
  • Set realistic think time (1–3 seconds) between requests
  • Don't test 3rd-party APIs you don't own (e.g., payment gateways)
  • Monitor system resources in Grafana while the test runs
  • Compare P95 latency, not just averages — P95 shows real user experience

🌐 Multi-Server Monitoring

  • Use consistent server_name labels (e.g., prod-app-1, prod-db-1)
  • Use environment tags (production/staging/dev) to group servers
  • Set up alerting in Grafana for CPU >85%, Disk >85%, and server offline events
  • Schedule monthly capacity reviews using the Fleet Overview dashboard

💡 Backup & Recovery
